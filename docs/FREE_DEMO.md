# Vibe Lab — 추가 인프라 비용 없는 평가 공개

## 선택한 방향

기존 PC에서 React/Express와 PostgreSQL을 실행하고, 외부 평가 때만 Cloudflare Quick Tunnel로 HTTPS 임시 주소를 제공합니다. AWS EC2/RDS·유료 도메인은 현재 생성하지 않습니다. 기존 PC·인터넷을 사용하므로 추가 서버/DB 임대료는 0원이며 전기·통신 비용은 별도입니다. PC 종료·절전·인터넷 끊김 시 접속도 중단됩니다.

```text
평가자 Chrome → 무료 HTTPS 임시 주소 → 내 PC의 Express(3001) → 로컬 PostgreSQL
                                          └→ 제공받은 키로 선택적 GPT 호출
코드 실행·테스트 → 학습자 브라우저
```

Quick Tunnel은 무료 개발·시험용이며 가동 시간을 보장하지 않습니다. 임시 주소는 재생성 시 달라질 수 있고, 동시 처리 중인 요청 200개 제한과 SSE 미지원 제약이 있습니다. 이는 사용자 200명을 보장한다는 뜻이 아닙니다. 현재 `server/ai.ts`의 AI 응답은 비스트리밍이지만 실제 공개 주소에서 기능 검증은 필요합니다. [Cloudflare 공식 안내](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

24시간 서비스·고정 주소·PC를 꺼도 접속 가능한 운영이 필요하면 별도 호스팅을 검토합니다. 이번 방식은 평가용 임시 공개입니다. 회사 네트워크에서 운영할 경우 외부 공개·터널 사용 허용 여부를 먼저 확인합니다.

## 제공받은 GPT 토큰 활용

키는 서버 환경변수 `OPENAI_API_KEY`에만 넣고 `OPENAI_MODEL`에 사용 권한이 있는 모델 ID를 설정합니다. 현재 코드는 OpenAI Responses API를 사용하며 일반 커리큘럼 생성에는 Structured Outputs도 필요합니다. 제공된 키가 다른 중계 서비스용이라면 그 접속 계약을 확인해야 합니다. 현재 구현에 임의의 API 주소 설정 기능이 있다고 가정하지 않습니다.

실습 과제는 키를 연결해도 검수된 규칙 기반 자료를 유지하는 코드 경로가 있습니다. 키 연결만으로 모든 실습이 자동 생성형 콘텐츠로 바뀌지는 않습니다.

토큰은 **이미 제공된 한도 안에서 사용**합니다. 실제 잔액·유효기간·허용 모델·자동 충전 또는 초과 과금 정책은 키 제공자/계정 관리자에게 확인합니다. 공유 계정의 전체 설정을 임의로 변경하지 않습니다. 키 자체에 독립적인 금액 잔액이 들어 있다고 가정하지 않습니다.

비용 절감 구현안:

- 기본 실행·테스트·힌트는 LLM 호출 없이 제공하고, 사용자가 AI 도움을 요청할 때만 호출합니다.
- 질문 길이·첨부 코드·최근 대화의 입력량과 모델별 출력/추론 토큰을 제한합니다. 입력·출력을 줄이는 방식은 OpenAI 비용 최적화 지침과 일치합니다. [공식 비용 최적화 안내](https://developers.openai.com/api/docs/guides/cost-optimization)
- 사용자별 하루 호출 한도와 전체 평가 기간 예산 한도를 서버에서 검사합니다. 동시 요청이 한도를 넘지 않도록 호출 전 예상 최대 사용량을 예약하고 사용량을 DB에 기록합니다.
- 한도 부족·초과·공급자 오류에는 새 AI 호출을 차단하고 기존 학습 힌트와 코드 실행을 계속 제공합니다. API 계정의 남은 크레딧보다 낮은 앱 한도를 둡니다.
- 실제 모델을 확인한 뒤 한 번의 작은 연결 검증부터 시작합니다. 토큰 수만으로 호출 가능 횟수를 단정하지 않습니다.

**현재 코드 상태:** AI 출력 한도(튜터 1,800 / 일반 커리큘럼 9,000 토큰)와 요청 횟수 제한은 있지만, 누적 사용량 예산 차단·일일 한도·소진 시 자동 규칙 모드 전환은 아직 구현되지 않았습니다. 이것들을 이미 적용한 것으로 안내하면 안 됩니다. 다른 앱도 같은 계정으로 토큰을 쓰는 경우 이 앱의 제한만으로 계정 전체 비용을 보장할 수 없습니다.

## 평가 공개 절차

1. 배포할 커밋을 확정하고 별도 PostgreSQL 테스트 DB에서 검증합니다. 학습용 DB는 백업합니다.
2. 기존 로컬 PostgreSQL을 사용합니다. 파일 저장 모드로 의도치 않게 바뀌지 않도록 `DATABASE_URL`과 고정 `SESSION_SECRET`을 확인합니다. AWS용 TLS 변수를 로컬 DB에 무조건 적용하지 않습니다.
3. 저장소 루트에서 `npm.cmd run build`로 운영 파일을 생성합니다. 개발 서버와 운영 서버가 같은 3001 포트를 동시에 사용하지 않도록 조정합니다.
4. cloudflared 설치를 확인한 후 별도 터미널에서 `cloudflared tunnel --url http://127.0.0.1:3001`을 실행합니다. 이 명령은 공개 주소를 만드는 단계이므로 실제 공개 시점에 실행합니다.
5. 발급된 HTTPS origin 전체를 서버의 `PUBLIC_ORIGIN`에 설정하고 `npm.cmd start`로 실행/재시작합니다. `HOST=127.0.0.1`을 유지합니다. 공유 대상은 5173 개발 서버가 아닌 3001 운영 앱입니다.
6. HTTPS 주소에서 로그인·가입·A/B 사용자 데이터 분리·CSRF·프로필·TS/SQL/R 실행·저장·외부 데이터·AI 실패 시 동작을 확인합니다. `PUBLIC_ORIGIN`을 설정하면 Secure 쿠키를 사용하므로 평문 localhost 로그인 결과와 혼동하지 않습니다.
7. 평가 시간 동안 PC와 DB·앱·터널을 켜둡니다. 주소가 바뀌면 `PUBLIC_ORIGIN`도 변경·재시작하고 새 주소에서 다시 로그인합니다.
8. 평가가 끝나면 터널을 종료합니다. 로컬 HTTP 개발로 돌아갈 때 `PUBLIC_ORIGIN`을 비우고 개발 서버를 다시 실행합니다.

불특정 다수에게 주소를 배포하기 전에 가입 접근 정책과 AI 전체 사용 한도를 적용합니다. 임시 주소를 아는 사람은 접속할 수 있으므로 URL 공유만으로 초대 전용 서비스가 되지는 않습니다.

위 절차는 현재 **작성된 실행 안내**입니다. 이번 작업에서는 환경변수 변경·앱 재시작·터널 공개·유료 API 호출을 실행하지 않았습니다. 후속 구현 순서는 ROADMAP의 FREE 작업을 따릅니다. 향후 AWS 전환 시 `docs/AWS_DEPLOYMENT.md`를 사용합니다.
